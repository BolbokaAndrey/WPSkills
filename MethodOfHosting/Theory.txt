1. Облако IaaS (Infrastructure as a service). AWS, Yandex Cloud
Это VPS + управляемые сервисы (БД, балансировщики, очереди)
+  высокая гибкость (автоматическое масштабирование под трафик)
+  Встроенные сервисы (мониторинг, ci/cd, безопасность)
+  Предсказуемая стоимость: фиксированная плата за месяц, удобно для стабильных нагрузок
+  Стабильная производительность: нет холодных стартов, ресурсы выделены

+-  Безопасность: (провайдер защищает облако, вы — данные в облаке)

-  зависимость от провайдера
-  Требует администрирования: обновления, патчи, мониторинг — ваша ответственность
-  Плата за простой: платите даже если сервер простаивает
-  Black box (Невозможность диагностики на уровне железа)
-  Vendor Lock-in: Сложно переехать из-за специфичных сервисов
Использовать для монолитного приложение: сложно разбить на функции, для высоконагруженных систем с постоянной нагрузкой

2. VPS
изолированная виртуальная машина на общей физической серверной платформе,
где ресурсы делятся между несколькими клиентами, но с гарантированным минимумом CPU/RAM
+  доступная цена
+  полный root-доступ
+  Предсказуемая производительность для средних нагрузок
+  Быстрое развертывание
+  Подходит для обучения

-  ограниченная масштабируемость
-  "шумные соседи" (производительность зависит от других VPS на хосте)
-  Низкая отказоустойчивость
-  Самостоятельное soft обслуживание
-  Ограничения на ресурсы
-  Миграция данных: При переезде провайдера/тарифа — ручной перенос, downtime и риски потерь
Использовать для Небольших веб-проектов с предсказуемой нагрузкой, микросервисы и фоновые задачи средней нагрузки, простые базы данных для небольших проектов

3. Выделенное железо
аренда или покупка полного физического сервера, где все ресурсы доступны только вам без соседей
+  максимальная производительность
+  контроль на уровне железа
+  нет соседей
+  низкая задержка в локальной сети
+  окупаемость при долгосрочной стабильной нагрузке
+  Кастомизация (Выбор конкретных компонентов)
+  Предсказуемость

-  высокие стартовые затраты
-  сложность масштабирования
-  ответственность за обслуживание и отказы
-  Зависимость от энергоснабжения/сетей
-  устаревание железа
-  Высокие косвенные затраты (возможный персонал, лицензии, электричество)
-  Ограниченная гео-распределенность
использовать для высоконагруженных систем со стабильной нагрузкой 24/7, для больших объёмов данных и хранилищ,
долгосрочных проектов с фиксированным бюджетом

4. Производительность vs Отказоустойчивость
Производительность важнее для задач с высокой вычислительной нагрузкой (машинное обучение, анализ данных, рендеринг видео),
где задача должна быть выполнена быстро, а перезапуск допустим
Одна мощная машина, локальные диски, отключение репликации для записи, либо облачные инстансы с высоким мощностями.
Как достигают:
    Вертикальное масштабирование (более мощный сервер).
    Кэширование (Redis, Varnish, CDN).
    Оптимизация запросов к БД.
    Использование локальных NVMe дисков (быстрее сетевых).

Отказоустойчивость — приоритет для критичных сервисов (e-commerce, Интернет-магазины, банки, мессенджеры, любые пользовательские сервисы)
Кластер из нескольких нод, балансировщик нагрузки, репликация данных. Облако лидирует за счет гео-репликации
Как достигают:
    Горизонтальное масштабирование (много серверов за балансировщиком).
    Репликация данных (Master-Slave, Multi-Master).
    Health-checks и автоматический перезапуск.

Для бизнес-критичных приложений отказоустойчивость важнее пиковой производительности одной ноды. Лучше медленнее, но всегда доступно.

5. KVM vs OpenVZ - технологии виртуализации
KVM - Аппаратная виртуализация, каждая VPS имеет свое ядро (своя ОС), изоляция на уровне железа, соседи не видят процессы друг друга,
гарантированные выделенные ресурсы, выше производительность, подходит для любых ОС и ресурсоемких задач,
масштабирование требует перезагрузки, высокая безопасность

OpenVZ - Виртуализация на уровне ОС (Контейнеризация), Все контейнеры делят ядро хост-машины (только Linux), шумные соседи могут мешать,
динамическое масштабирование без даунтаймов, ниже безопасность из-за слабой изоляции.

Для ресурсоемких задач, где нужна изоляция и стабильность лучше использовать KVM
Для дешевых Linux-only проектов с низкой нагрузкой где скорость важнее безопасности использовать OpenVZ
Для продакшена - стандарт KVM

6. Диски
HDD - дешево, большой объем, но медленные (до 500 MB/s) и низкие IOPS (IOPS - операции ввода-вывода в секунду)
Хорошо использовать для файловых помоек, бэкапов, где скорость не нужна

SSD (SATA) - дороже, скорость выше (500-7000 MB/s)
Для небольших бд, средних задач

SSD (NVMe) - дорогие, ресурс записи ограничен, очень низкая задержка, высокие IOPS
Высоконагруженные бд, кеш, высоконагруженные сервисы

Сетевые диски (Cloud Drive / EBS) - физический носитель данных находится не в том же сервере, где работает ВМ
Можно отключить от одного сервера и прикрепить к другому. Высокая надежность (данные реплицируются)
Задержка выше, чем у локального диска. Зависит от сети

7. Serverless (FaaS - Function as a Service)
Вы загружаете код, провайдер запускает его только при событии (HTTP запрос, таймер, загрузка файла). Оплата за выполнение
+  авто-масштаб
+  Нет администрирования
+  нулевые затраты в покое
+  быстрая разработка

-  холодный старт
-  Ограничение на время выполнения, память, размер пакета
-  Vendor Lock-in (привязка к экосистеме провайдера)
-  Сложность отладки

Использобавть для обработка событий, крон-задачи, API бэкенды с нестабильным трафиком, обработка файлов. не для long-running процессов.
