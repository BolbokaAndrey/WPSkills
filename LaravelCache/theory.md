# Основы кэширования

## Что такое кэширование и каковы его преимущества в контексте веб-разработки на Laravel?

Кэширование — временное хранение данных в быстром хранилище. Оно уменьшает число запросов к БД, нагрузку на сервер и время ответа.

## Какие типы драйверов кэша поддерживает Laravel?

Laravel поддерживает следующие драйверы:

- `array` — хранит данные только в памяти текущего PHP-процесса; удобен для тестов.
- `file` — хранит сериализованные данные в файлах.
- `database` — хранит записи в таблице базы данных.
- `redis` — хранит данные в памяти Redis; подходит для production и масштабирования.
- `memcached` — высокопроизводительное распределённое хранилище в памяти.
- `dynamodb` — хранит кэш в AWS DynamoDB.
- `octane` — хранит данные в памяти Laravel Octane; кэш локален для процесса/воркера.
- `null` — ничего не сохраняет; полезен для отключения кэша.

Также возможны сторонние драйверы, например MongoDB.

# Работа с кэшем

## Как сохранить данные в кэш с использованием Laravel?

```php
Cache::put('key', $value, now()->addMinutes(10));
Cache::add('key', $value, 3600); #записать, если ключа нет
Cache::forever('key', $value); #записать без срока истечения
Cache::remember('key', 600, fn () => $value); #получить из кэша или сохранить результат callback
```

## Как проверить, существуют ли данные в кэше?

```php
Cache::has('key');
```

## Как удалить данные из кэша?

```php
Cache::forget('key');
```

## Как можно использовать теги кэша в Laravel и для чего они нужны?

Теги объединяют связанные записи, чтобы очистить их одной командой. Поддерживаются Redis и Memcached:

```php
Cache::tags(['users'])->put('user:1', $user, 3600);
Cache::tags(['users'])->flush();
```

# Конфигурация кэша

## Как настроить систему кэширования в Laravel?

Настройки находятся в `config/cache.php`, активный драйвер задаётся в `.env`:

```env
CACHE_STORE=redis
```

## В чем разница между кэшированием "file" и "redis" в Laravel?

`file` хранит кэш в файлах: прост и подходит для разработки. `redis` хранит его в памяти отдельного сервера: быстрее, удобен для нескольких экземпляров приложения, поддерживает теги и блокировки.

## Как изменить время жизни (TTL) кэшированных данных?

Передать время третьим аргументом `put` или вторым аргументом `remember` (нет):

```php
Cache::put('key', $value, 3600);
Cache::remember('key', 600, fn () => $value);
```

```php
Cache::touch('key', 3600);
```

# Продвинутое кэширование

## Как реализовать кэширование запросов к базе данных в Laravel?

Обернуть запрос в `Cache::remember`:

```php
$users = Cache::remember('users.all', 3600, fn () => User::all());
```

## Как использовать кэширование для ускорения отдачи контента пользователям?

Кэшировать результаты запросов, API-ответы, фрагменты страниц или готовые HTTP-ответы; при изменении исходных данных обновлять или сбрасывать кэш.

## Как сбросить кэш приложения Laravel командой Artisan?

```bash
php artisan cache:clear
```

# Лучшие практики и отладка

## Какие существуют лучшие практики по кэшированию в Laravel, направленные на улучшение производительности приложения?

- Кэшировать дорогие и часто читаемые операции: выборки из БД, результаты API и сложные вычисления.
- Давать ключам понятные имена и добавлять контекст: `user:15:profile`, `products:page:1`.
- Всегда выбирать TTL: короткий для часто меняющихся данных, длинный — для стабильных.
- Инвалидировать кэш при изменении исходных данных: например, удалить `user:15` после обновления пользователя.
- Не кэшировать пароли, токены и чужие персональные данные в общих ключах.
- Для нескольких серверов использовать общее хранилище, например Redis, а не `file`.
- Предотвращать одновременное заполнение одного пустого ключа с помощью `Cache::lock()`.
- Измерять эффект: кэш полезен, если снижает время ответа и число запросов, а не только увеличивает объём памяти.

## Как отлаживать проблемы с кэшированием в Laravel?

1. Проверить выбранный драйвер в `.env` (`CACHE_STORE`) и настройки в `config/cache.php`.
2. Проверить ключ, значение и срок жизни: `Cache::has('key')`, `Cache::get('key')`.
3. Убедиться, что Laravel не использует старую конфигурацию; выполнить `php artisan config:clear`.
4. Очистить данные командой `php artisan cache:clear`, если нужно исключить устаревший кэш.
5. Для Redis проверить наличие и TTL ключа через `redis-cli`: `GET key`, `TTL key`.
6. Добавить временное логирование около `Cache::get`, `put`, `remember` и проверить, выполняется ли callback у `remember`.

Не следует очищать весь production-кэш при каждой проблеме: сначала нужно определить конкретный ключ и причину его устаревания.

## Какие инструменты или пакеты Laravel можно использовать для управления кэшированием и мониторинга его эффективности

**Laravel Telescope.** Установить и открыть панель `/telescope`:

```bash
composer require laravel/telescope --dev
php artisan telescope:install
php artisan migrate
```

На вкладке Cache видны попадания в кэш, промахи, запись и удаление ключей. На вкладках Queries и Requests можно проверить, уменьшилось ли число SQL-запросов. В production доступ к `/telescope` обязательно ограничивают через `TelescopeServiceProvider`.

**Laravel Pulse.** Установить и открыть `/pulse`:

```bash
composer require laravel/pulse
php artisan vendor:publish --provider="Laravel\Pulse\PulseServiceProvider"
php artisan migrate
```

На панели смотрят slow requests, slow queries, jobs и нагрузку сервера до и после внедрения кэша. В production доступ к `/pulse` ограничивают политикой `viewPulse`.

**Laravel Debugbar.** Используют только локально:

```bash
composer require fruitcake/laravel-debugbar --dev
```

При `APP_DEBUG=true` панель появится внизу страницы. В ней проверяют число и время SQL-запросов, время обработки HTTP-запроса и память. Можно добавить своё сообщение или замер:

```php
Debugbar::info(Cache::has('key'));
Debugbar::measure('load-users', fn () => Cache::remember('users', 600, fn () => User::all()));
```

**Redis Insight или `redis-cli`.** Позволяют посмотреть фактические ключи и их TTL в Redis:

```bash
redis-cli
GET laravel_cache:key
TTL laravel_cache:key
```

В Redis Insight это же делают через графический интерфейс. Не следует выполнять `KEYS *` на большом production-хранилище: команда может блокировать Redis; безопаснее использовать `SCAN`.

**Spatie Laravel Responsecache.** Устанавливают пакет и назначают middleware только публичным GET-маршрутам:

```bash
composer require spatie/laravel-responsecache
```

```php
use Spatie\ResponseCache\Middlewares\CacheResponse;

Route::middleware(CacheResponse::for(minutes(10)))
    ->get('/posts', [PostController::class, 'index']);
```

Первый запрос создаёт ответ, последующие получают его без выполнения контроллера. Не следует применять такой кэш к персонализированным страницам без настройки ключа кэша и исключений.

# Атомарные блокировки

## Что такое атомарные блокировки и для чего используются?

Это механизм, который разрешает критический код только одному процессу одновременно. Используется, чтобы не создать дубликаты и не выполнять одну тяжёлую задачу параллельно.

Примеры критического кода:

1. **Покупка последнего товара.** Два пользователя не должны одновременно уменьшить остаток с `1` до `0` и оба оформить заказ.

```php
Cache::lock("product:{$productId}:purchase", 10)->block(3, function () use ($productId) {
    DB::transaction(function () use ($productId) {
        $product = Product::findOrFail($productId);

        if ($product->stock < 1) {
            throw new RuntimeException('Товара нет в наличии');
        }

        $product->decrement('stock');
        Order::create(['product_id' => $product->id]);
    });
});
```

2. **Повторный платёжный webhook.** Один и тот же webhook может прийти несколько раз; заказ нужно отметить оплаченным только один раз.

```php
Cache::lock("payment:{$paymentId}", 30)->block(5, function () use ($paymentId) {
    $payment = Payment::findOrFail($paymentId);

    if (! $payment->is_paid) {
        $payment->update(['is_paid' => true]);
        // выдать доступ, отправить событие и т. п.
    }
});
```

3. **Генерация тяжёлого отчёта.** Несколько запросов не должны параллельно создавать одинаковый отчёт.

```php
Cache::lock("report:{$reportId}:generate", 300)->block(5, function () use ($reportId) {
    ReportService::generate($reportId);
});
```

Для операций с БД блокировку обычно сочетают с транзакцией: `DB::transaction(...)`. Блокировка координирует процессы, а транзакция сохраняет целостность данных при ошибке.

## Получение, добавление и снятие блокировки.

```php
$lock = Cache::lock('report:generate', 10);

if ($lock->get()) {
    try {
        // критическая секция
    } finally {
        $lock->release();
    }
}
```

`get()` получает блокировку, `release()` снимает её, `10` — её TTL в секундах.

## Как задать условие блокировки.

У блокировки задают три условия:

1. **Имя** — общий идентификатор ресурса, который нельзя обрабатывать параллельно: `order:15:payment` или `product:7:purchase`.
2. **TTL** во втором аргументе `Cache::lock()` — сколько секунд блокировка существует. Он должен быть чуть больше максимального времени критического кода: `Cache::lock('report:1', 60)`.
3. **Правило получения** — немедленная попытка через `get()` либо ожидание через `block()`.

`get()` не ждёт: возвращает `true`, если блокировка получена, и `false`, если она занята. Это подходит, когда можно сразу вернуть пользователю ответ «операция уже выполняется»:

```php
$lock = Cache::lock("order:{$orderId}:payment", 30);

if (! $lock->get()) {
    return response()->json(['message' => 'Платёж уже обрабатывается'], 409);
}

try {
    PaymentService::process($orderId);
} finally {
    $lock->release();
}
```

Вариант `get(callback)` также запускает callback только при успешном получении блокировки и автоматически освобождает её после выполнения:

```php
Cache::lock("report:{$reportId}", 60)->get(function () use ($reportId) {
    ReportService::generate($reportId);
});
```

`block(5)` ждёт освобождения блокировки максимум пять секунд. Если она не получена вовремя, Laravel выбрасывает `LockTimeoutException`. При передаче callback блокировка освобождается автоматически:

```php
use Illuminate\Contracts\Cache\LockTimeoutException;

try {
    Cache::lock("report:{$reportId}", 60)->block(5, function () use ($reportId) {
        ReportService::generate($reportId);
    });
} catch (LockTimeoutException $e) {
    return response()->json(['message' => 'Отчёт уже создаётся'], 409);
}
```

На нескольких серверах нужен общий драйвер кэша, обычно Redis; локальный `file`-кэш не синхронизирует блокировки между серверами. Если критическая работа может длиться дольше TTL, TTL нужно увеличить или обновлять блокировку, иначе другой процесс сможет начать ту же работу раньше времени.
